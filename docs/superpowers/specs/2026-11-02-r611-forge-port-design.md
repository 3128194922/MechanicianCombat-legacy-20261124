# MechanicianCombat r611 Forge 移植说明

## 目标与范围

将上游 OrcosD-art/MechanicianCombat 的 d77964051c97e9138c1054d016933a7ef1dab005（r611）内容移植到现有主项目，目标保持 Minecraft 1.20.1、Forge 47.4.28 和 Java 17。对照本地 r396 参考源码与现有实现逐项核实代码及资源，不能仅以文件名判断功能已完成。上游变更包括 PlayerAnimator 动作、Veritas 近战和冲击反馈、Silent Storm、Fortress 技能、机械师护甲与闪避，以及相关状态、网络、特效、模型、音效和修复。

## 约束

- 只修改主项目，保留已有未提交修改；上游及参考项目只读。保留注册 ID、资源名、动作时序和玩法，尊重既有用户决定，例如 Curios 背包和熔铁弩矢忠诚规则。
- 使用现有 Forge/Java 17 接口重写 Fabric 1.21.1 的注册、网络、事件、物品数据及渲染，服务端负责战斗权威；客户端逻辑与专服隔离。
- 只使用已批准的前置。新依赖、无等价 API 或必须改变玩法的部分单独标记并询问用户，其他独立功能继续。
- 上游内衬使用 Accessories，目标项目已批准用 Curios 取代 Accessories。具体槽位及与现有背包共存方式在核实上游槽位配置和 Curios 1.20.1 机制后确定；如存在会改变装备玩法的歧义则询问用户。

## 实施和验收

1. 固定 r611 源码版本，建立相对 r396 和当前工程的逐项差异清单；记录每项实现状态和不兼容项。
2. 按服务端规则、物品与资源、客户端动作与渲染、网络同步顺序移植，逐步整合现有代码，不覆盖用户改动；检查所需资源和许可证。
3. 对关键状态、装备门槛、攻击/冷却和消息校验进行有意义的验证，运行项目适用的构建、契约检查和 GameTest；分别报告客户端、专服、多人和视觉实测状态。
4. 更新移植记录及依赖清单，生成标识目标版本的 JAR 并记录哈希；构建通过不等于游戏内验收通过。

不改其他模组，不引入兼容加载层，不将新增内容做成占位功能。项目没有证据的实机验收项目保持未验证。
